## How I work

I start with the real product interaction and the constraints underneath it. Then I make ownership, failure behavior, and verification part of the implementation.

- **Model the whole path.** Keep interfaces, data, and integrations working from the same rules.
- **Design for interruption.** Treat retries, stale state, offline use, and human correction as normal behavior.
- **Show the evidence honestly.** A source change, a fixture demo, a device test, and a production release prove different things.

I stay hands-on from architecture and implementation through release and maintenance, using AI within a reviewed and verified engineering workflow.
